1 The application

1.1 The problem

Developers now read more code than they write. A coding agent produces a feature in minutes. A teammate opens a pull request that touches dozens of files. A new job or a course project such as CS2103 starts in a codebase that someone else built over years. In each case the developer has to understand code they did not write before they can change it safely.

The usual answer is to ask the agent. A chat answer disappears with the session. The next question costs a full exploration of the repository again, and the answer cites nothing the developer can check. Our interviews found developers who read every line an agent writes and developers who avoid autonomous agents for this reason. Both groups spend time building a picture of the code that nothing keeps for them.

1.2 What aisus does

aisus turns a repository into a map. The map is a diagram of boxes and arrows, and every box cites the files and line ranges it describes. A click on a box opens those lines beside the map.

aisus makes no AI calls of its own. The developer's own coding agent, such as Claude Code, Codex or Devin, draws the map by following an aisus skill. The skill's first script collects facts about the repository. The agent reads the code and writes a draft. The skill's validator then checks the draft. It refuses a box that cites a file outside the repository, a line that does not exist or a secret such as a .env file, and it tells the agent what to fix. When the draft passes, the validator saves the map with a fingerprint of every cited line.

The fingerprints keep the map honest after the code changes. Whenever a cited file changes, the editor compares the code with the fingerprints and marks each box as fresh, moved, edited or missing. A moved box still opens at the right lines. This check runs no agent and spends no tokens. Refresh then asks the agent to redraw only the edited and missing boxes, so its cost follows the size of the change rather than the size of the repository.

Maps are plain JSON files in .aisus/maps/. A team commits them with the code, and every teammate gets them with the next pull. The extension itself sends nothing over the network.

1.4 A walkthrough

A developer installs aisus from the VS Code Marketplace and clicks the aisus icon in the Activity Bar. The sidebar's setup checklist names anything missing, such as Node.js or a signed-in agent, and offers a fix for each. The developer picks Claude Code as the agent.

The developer types an optional focus, such as "payment flow", and reads the token estimate under Generate. A click on Generate starts the agent, and the sidebar shows its progress and the tokens it spends. When the validator accepts the draft, the map opens.

Hovering a box shows its description and every source it cites. A click opens the cited lines beside the map with the lines selected. The developer commits the map folder, and the team gets the same map with the next pull.

A week later a teammate opens a pull request. The developer checks out the branch and opens Review changes in the sidebar. aisus compares the branch with its base and highlights the boxes the change touches, the boxes it leaves stale and the changed files no box covers. The developer reads the highlighted boxes first. Refresh then updates only those boxes, and the GitHub Action posts the same report on the pull request.
