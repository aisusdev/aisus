1 The application

1.1 What aisus is

aisus draws a repository as a map. Each box on the map stands for a part of the system and cites the files and lines it describes. A click on a box opens those lines in the editor.

The developer's own coding agent draws the map. aisus gives the agent a skill to follow, and it checks every citation before it saves the map. After that, aisus compares the map with the code whenever the code changes. It marks each box whose code has changed, and the check costs no tokens. Refresh asks the agent to redraw only the marked boxes.

aisus runs as a VS Code extension, an IntelliJ IDEA plugin and a set of agent skills. aisus cloud at aisus.dev shares maps with a team. A GitHub Action reports which boxes each pull request changes.

1.2 The symptom

Agents now write code faster than people can read it. A developer can accept a day of changes in an afternoon and still not know how the system fits together. We call this gap comprehension debt. It costs nothing until something breaks. Then the team pays it all at once and learns the system under pressure.

Agents do not close the gap. An agent reads a few files at a time within its context window, and its picture of the system ends with the session. It can explain one function well and still miss how two services depend on each other.

Microsoft's outage of 12 to 14 November 2026 shows how large systems fail where their parts meet. Exchange Online and other Microsoft 365 services stopped working around the world. Microsoft's summary of the root cause named several causes. A defect deployed in July made networking gateway servers stop responding under certain loads. A change in how traffic was allocated raised that load. Maintenance had already cut the gateway fleet's capacity by 14%. At the peak, more than 80% of the gateway servers did not respond. The boundary meant to keep a failure inside one region did not hold. Automated rollback could not help, because the faulty change was four months old. Microsoft said AI agents did not cause the outage.

None of these causes was unusual on its own. The outage came from the way they combined, and the defect went undetected for four months. A review of one change at a time does not show how the parts of a system meet. A map of the whole system shows where they meet.

1.3 The vision

Each step in programming has raised the level at which people work. Unix was first written in assembly. C let Bell Labs rewrite it in a higher-level language and move it to new machines. C left programmers to manage memory by hand, and Python let them stop. Now code itself is too much to write, and agents write it for us.

We see two ways this can go. In the first, agents reach general intelligence. Agents then do all of the work, and most programming jobs end. In the second, agents stop improving at the rate they have, and the chain continues. Something will sit above code, the way code sits above assembly. We build for the second case, as a hedge against the first.

We predict that the next step is visual. People understood the world by seeing it long before they read or wrote. Engineers already explain systems to each other with boxes and arrows on a whiteboard. aisus makes that drawing from the code, links each box back to its code and keeps the drawing true as the code changes. aisus is a first step towards working with software through its structure instead of its text.
