## Proposals

### P-26 Estimates from this folder's runs, and an optional detailed estimate (2026-11-01)

Estimates stay far below what runs spend. This repository's one recorded run spent 1.46M tokens ($1.49) against "About 160k–320k tokens". Every estimate is scaled by the median ratio of spent to estimated tokens over the last five finished runs in the same folder, by the same agent and of the same kind. A new setting, `aisus.estimate.detailed`, is off by default. When it is on, Generate first plans which files the focus will read, then shows the planned reads, turns and tokens and waits for a second click.

The detailed estimate counts each turn's whole context again, because 93% of that run's tokens were cache reads. Tokens are about T × P + R × (T + 1) / 2 + O. T is the planned turns: the tier's read budget plus validator and write turns. P is the prompt and skill per turn. R is the planned read tokens, from the planned files' byte sizes. O is the output. The planned files are those whose paths match the focus words, up to the read budget, and files at the folder's median size fill the rest. The constants start provisional and the folder's runs calibrate them. A past run's prediction is recomputed from today's files and its `focus` in `run.json`, so `run.json` keeps its format.

- `[unit]` Doubling the planned reads more than doubles the detailed estimate, and the result matches the formula worked by hand for one plan.
- `[unit]` A focus naming one folder plans only that folder's files, and an empty focus plans the tier's full budget.
- `[e2e]` With `aisus.estimate.detailed` on, the first Generate click shows the detailed line and starts no run, and the second click starts it.

Where the build differs:
- No new message type. The sidebar's first click on an armed Generate sends the existing `generate` without `confirmed`, which the host already ignored. With the setting on, the host plans that focus instead. `messages.ts` is unchanged.
- `readPlan(files, focus, tier)` takes the listed files from `planFiles(root)`, so one listing serves the new plan and every past run's plan. The plan text comes from `planText`, and `detailedRunEstimate` joins the estimate, the plan and the calibration.
- A changed focus disarms Generate, so the stated plan is for the focus that runs.
- The calibration test uses ratios of 2, 3 and 7, whose median of 3 differs from their mean of 4. The proposed 3 and 5 could not tell a median from a mean.
- The e2e test also checks that the run card keeps the detailed estimate.
- Outside the table: the README's cost section gains two lines, the DOM test of the second click now expects the first click's unconfirmed `generate` (+3 / -3), `test/unit/boundaries.test.ts` lists `readPlan.ts` as a core module that uses Node (+1), and `npm run build` refreshes the three bundled fact scripts.
