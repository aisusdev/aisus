### P-33 Publish a map with one click in VS Code (2026-11-01)

Publishing takes a setting, a menu, a space choice, a JSON preview and a confirmation today. A Publish button beside each map in the sidebar sends it to the repository's team space with one click. That is the map the repository page on aisus.dev shows for the checked-out branch.

| File or unit | Change | Estimate | Built |
|---|---|---|---|
| `packages/viewer/home.ts` | A Publish button beside each map's title, outside the ⋯ menu | +6 / -0 | |
| `packages/core/model/messages.ts` | The `publishMap` message | +1 / -0 | |
| `apps/vscode/src/home.ts` | Routes `publishMap` to the command | +3 / -0 | |
| `apps/vscode/src/cloud.ts` | `publishMapCommand` builds the upload for the checked-out branch, runs `checkUpload`, sends it to the team space and shows "Published" with Open in aisus cloud. It shares the payload code with `shareMapCommand` | +40 / -15 | |
| `apps/vscode/package.json` | `aisus.cloud.enabled` defaults to true, per the second question below | +1 / -1 | |
| `docs/messages.md` | The `cloud-published` notification | +1 / -0 | |
| `docs/architecture.md` | The `publishMap` message and the one-click publish | +2 / -0 | |

Tests:
- `[dom]` The sidebar shows Publish beside each map while the cloud is on, and no Publish while it is off.
- `[e2e]` One click on Publish sends the map to the team space with no prompt after GitHub sign-in.
- `[e2e]` A map that `checkUpload` refuses sends nothing and shows the refusal.

Questions before building:
1. The click replaces the JSON preview and the confirmation. The secret scan in `checkUpload` still runs before anything is sent. ADR 0055 holds, because the click is the user asking.
2. `aisus.cloud.enabled` is off by default, so the button would be hidden for most users. Turning it on by default shows Publish to everyone, and nothing is sent until a click.
3. Share to aisus cloud stays in the ⋯ menu for the personal space and the preview.
