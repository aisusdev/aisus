### PRC-07 Pull request diagrams from a skill (2026-10-30)

The owner asked for a way to post a diagram that explains a pull request's changes as a comment on it, with an image of the diagram and a link to its page in aisus cloud. A new skill, `aisus-pr`, does it from the user's own coding agent. `/aisus-pr` without instructions shows the pull request's changes on the main map. `/aisus-pr <instructions>` has the agent read the change and draw a map that answers the instructions in natural language. Each run adds one diagram to the pull request, so a pull request can collect many. The feature comes with Pro and the plans above it.

The skill runs in Claude Code, Codex or Devin on the pull request's checked-out head:

1. `gh pr view` gives the pull request for the current branch. The skill stops when the checked-out commit is not the pull request's head.
2. `pr-facts.mjs` creates a run folder of kind `pull` with the pull request's number, base, head, merge-base and changed files.
3. Without instructions, `aisus.mjs check` gives the delta on the main map. With instructions, the agent reads the changed code and writes `draft.json`, and `validate.mjs` must accept it.
4. `aisus.mjs publish --pull <n>` uploads the diagram to aisus cloud with the repository's `AISUS_TOKEN`, and prints the diagram's page and image addresses.
5. `gh pr comment <n>` posts the image, the instructions quoted, and Open in aisus cloud, as the user who ran the skill.

The cloud stores each diagram, never an image. `GET /api/v1/images/<token>.svg` lays the stored diagram out and draws it on every request, with an immutable cache header for GitHub's image proxy. Only the token's SHA-256 is stored. The route sits under `/api/` because a top-level route would take the place of an account's maps, as `/<owner>/team` does (P-21).
