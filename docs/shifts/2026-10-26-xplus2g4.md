## Proposals

### CLD-19 Cloud status strip (2026-10-26)

The sidebar never says whether aisus cloud is connected. Of five mocked variations the owner picked an account strip at the foot of the home page. It shows one of four states: off with Turn on, on without a GitHub sign-in with Sign in with GitHub, connected with the account and the pulled maps, and unreachable with the age of the last pull and Try again.

| File or unit | Change | Estimate | Built |
|---|---|---|---|
| `packages/core/model/messages.ts` | `CloudStatus` union and `HomeState.cloudStatus`, `null` until the first pull ends. Messages `cloudTurnOn`, `cloudSignIn`, `cloudRetry` | +15 | +17 |
| `apps/vscode/src/cloud.ts` | `cloudAccount()` reads the GitHub sign-in silently. `branchCloudMaps` returns `null` when it asked the cloud nothing | +12 / -4 | +26 / -5 |
| `apps/vscode/src/home.ts` | `pullCloudMaps` records the status, an unreachable cloud included. The three messages open the setting, sign in, or pull again | +40 / -6 | +40 / -6 |
| `packages/viewer/home.ts` | `renderCloud` draws the strip as the home page's last element | +40 | +42 / -1 |
| `packages/viewer/sidebar.css` | The strip sits at the foot of the view, with an initial for an avatar and a state dot | +45 | +88 |
| `docs/architecture.md` | The sidebar protocol lists `cloudStatus` and the three messages | +1 / -1 | +1 / -1 |

Tests:
- `[dom]` Each of the four states shows its words, and its link posts its message.
- `[e2e]` With a sign-in and a reachable cloud, the sidebar's state is connected as the signed-in account with a pull time.

Where the build differs: `cloud.ts` also gained `cloudHost()` and `signInToCloud()`, and the host pulls again when the GitHub sign-in changes. The stylesheet grew past its estimate because the strip pins to the foot of the view. The tests added 20 lines to the dom suite and 14 to the e2e suite.

### CLD-19 Status bar warning for an unreachable cloud (2026-10-26)

The owner asked for the status bar half of the recommendation too. A second status bar item appears only while aisus cloud can't be reached, on the warning background, so the outage shows with the sidebar closed. A click opens the sidebar, whose strip offers Try again.

| File or unit | Change | Estimate | Built |
|---|---|---|---|
| `apps/vscode/src/home.ts` | `onDidChangeCloud` fires with each recorded status. Turning the cloud off records off even while the sidebar is hidden | +10 / -2 | +8 / -2 |
| `apps/vscode/src/statusBar.ts` | `CloudWarningItem` shows "aisus.dev unreachable" with the warning background, and hides in every other state | +30 | +36 |

| `docs/architecture.md` | The `statusBar.ts` row names the warning | +1 / -1 | +1 / -1 |

Tests:

Where the build differs: nothing beyond the sizes. The e2e test added 13 lines.
